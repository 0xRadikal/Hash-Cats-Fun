# مکانیک فنی قرارداد Hashcats

مستند دقیق مکانیک قرارداد، همه‌ی موارد **مستقیماً از روی زنجیره** استخراج و
صحت‌سنجی شده‌اند.

## آدرس‌ها و شبکه

| مورد | مقدار |
|------|-------|
| شبکه | Robinhood Chain، `chainId = 4663` |
| RPC | `https://rpc.mainnet.chain.robinhood.com` (پشتیبان: `https://robinhood.drpc.org`) |
| قرارداد کالکشن | `0xCA75DF55Cc9C476DB27a7375D1fc8E794cf80721` |
| Multicall3 | `0xca11bde05977b3631167028862be2a173976ca11` |
| Explorer | `https://robinhoodchain.blockscout.com` |

## تابع mint

```solidity
mine(uint256 nonce, uint256 anchorBlock) payable returns (uint256 tokenId)
```

- سلکتور واقعی: `0x071e9503` (با تراکنش‌های واقعی روی زنجیره تطبیق داده شد)
- `msg.value` باید **دقیقاً** برابر `mintPrice()` باشد؛ در غیر این صورت خطای
  `WrongPayment`.
- ترتیب بررسی داخل قرارداد: **اول پرداخت، بعد راه‌حل**. (با تست خطاها تأیید شد:
  nonce نامعتبر + value=0 → خطای `WrongPayment`، نه `BadSolution`.)

## فرمول اثبات کار (PoW)

```
workHash = keccak256( abi.encodePacked(miner, nonce, prevWork, anchorHash) )
شرط برد:  workHash < targetFor(miner)
```

- ترتیب و نوع پارامترها (از ABI): `miner:address، nonce:uint256، prev:uint256،
  anchor:bytes32`.
- این فرمول با فراخوانی `workHash(...)` روی خود قرارداد برای چند nonce تصادفی
  آزمایش شد و خروجی محلی ما **دقیقاً برابر** خروجی on-chain بود.

## توابع خواندنی مهم

| تابع | معنی |
|------|------|
| `mintPrice()` | قیمت ورودی فعلی (wei) |
| `currentTarget()` | هدف سختی فعلی (سراسری) |
| `targetFor(address)` | هدف سختی برای یک ماینر (در عمل = سراسری) |
| `currentBurst()` | مقدار burst فعلی شبکه |
| `prevWork()` | «کار» گربه‌ی قبلی (با هر mint عوض می‌شود) |
| `currentAnchor()` | `(anchorBlock, anchorHash)` جاری |
| `totalMinted()` | تعداد گربه‌های ضرب‌شده |
| `currentEpoch()` | epoch فعلی (روی قیمت و کف سختی اثر دارد) |
| `targetAt(id,base,floorBits,idle,burst)` | تابع خالص محاسبه‌ی هدف |

## مدل سختی (Difficulty)

```
بیت‌های سختی = کفِ epoch (فعلاً 32) + burst
```

- `FLOOR_BITS = 26`، کفِ epoch فعلی ۳۲ بیت (از `epochFloor` خوانده شد).
- هر mint شبکه، `burst` را +۱ می‌کند (سختی ۲ برابر).
- `DECAY_HALFLIFE = 10` ثانیه: هر ۱۰ ثانیه بدون mint، `burst` یک واحد کم می‌شود.
- سختی **سراسری** است. آزمایش‌ها نشان داد `personalBurst`/آدرس تازه هیچ تخفیفی
  در `targetFor` نمی‌دهد.

## پنجره‌ی anchor

- `ANCHOR_WINDOW = 250` بلاک. آزمایش نشان داد `anchorBlock`های نسبتاً قدیمی هم
  پذیرفته می‌شوند؛ پس anchor گلوگاه اصلی نیست.
- گلوگاه واقعی `prevWork` است که با **هر** mint (توسط هر کسی) عوض می‌شود و
  تلاش‌های در جریان را باطل می‌کند.

## خطاهای قرارداد (نمونه)

`BadSolution`، `WrongPayment`، `OneCatPerBlock`، `CatTooFresh`،
`NoNextCatYet`، `TokenAlreadyExists` و … (کل فهرست در `hashcats_abi.json`).

## نکات صحت‌سنجی انجام‌شده

1. تطبیق `workHash` محلی با on-chain برای چند nonce تصادفی → یکسان.
2. حل یک هدف آسان و تأیید راه‌حل توسط قرارداد → معتبر.
3. شبیه‌سازی `mine` با value نادرست → خطای `WrongPayment` (مسیر تراکنش درست).
4. کالبدشکافی تراکنش‌های واقعی برنده‌ها → سختی ~۴۸ بیت واقعاً حل شده بود.
5. تطبیق selector `mine` محلی با selector واقعی روی زنجیره (`0x071e9503`).
